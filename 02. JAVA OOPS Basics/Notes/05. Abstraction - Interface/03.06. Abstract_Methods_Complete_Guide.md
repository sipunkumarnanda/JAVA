# 🌟 Introduction

In **Chapter 3**, we learned about **Abstract Classes**.

We saw that an abstract class can contain:

* 📦 Variables
* 🏗 Constructors
* ⚙️ Concrete Methods
* 🏛 Abstract Methods
* 📌 Static Methods
* 🔒 Final Methods

Among all these members, the **most important** is the **Abstract Method**.

An abstract class exists mainly because of abstract methods.

Without abstract methods, an abstract class would simply behave like a normal class (except that it couldn't be instantiated).

So before learning the rules, let's answer one question.

> **Why did Java introduce Abstract Methods?**

---

# 🤔 What is an Abstract Method?

An **Abstract Method** is a method that has:

* ✅ A declaration
* ❌ No implementation (no method body)

It tells the child class:

> **"You must provide the implementation."**

General syntax:

```java
abstract returnType methodName(parameters);
```

Example:

```java
abstract class BankAccount{

    abstract void deposit(double amount);

}
```

Notice carefully.

This method has

* Method Name ✅
* Return Type ✅
* Parameters ✅
* Semicolon ✅

But it has

```java
{

}
```

❌ No method body.

---

# 📖 Official Definition

> **An Abstract Method is a method declared with the `abstract` keyword that contains only a declaration and no implementation. Every concrete subclass must provide its own implementation.**

# 🤔 What Should the Parent Class Do?

Should the parent write

```java

}
```

No.

Because the parent **doesn't know** how every future account will implement deposit.

Instead,

the parent simply declares

```java

```

This means

```text
Every BankAccount

↓

Must Support Deposit

↓

Child Will Decide How
```

# 🤔 Why Doesn't an Abstract Method Have a Body?

This is one of the most common interview questions.

Consider this method.

```java
abstract void deposit(double amount);
```

Question:

Why doesn't Java allow

```java
abstract void deposit(double amount){

    System.out.println("Deposit");

}
```

The answer is simple.

The purpose of an abstract method is

> **to force child classes to provide their own implementation.**

If Java allowed a body,

then the method would already have an implementation.

It would no longer be abstract.

---

# 🎯 Responsibility Principle

Think about responsibilities.

Parent Class

```text
Defines

↓

WHAT
```

Child Class

```text
Defines

↓

HOW
```

If the parent also implemented the method,

then both parent and child would share responsibility.

Java avoids this confusion.

One responsibility.

One implementation.

Cleaner design.

# 🚨 What Happens If a Child Doesn't Implement It?

Parent

```java
abstract class BankAccount{

    abstract void deposit(double amount);

}
```

Child

```java
class SavingsAccount extends BankAccount{

}
```

Compiler Error ❌

Why?

Because `SavingsAccount` is a **concrete class**.

A concrete class must provide implementations for all inherited abstract methods.

---

# ✅ Two Ways to Fix It

### Option 1

Implement the method.

```java
class SavingsAccount extends BankAccount{

    @Override
    void deposit(double amount){

        System.out.println("Deposit");

    }

}
```

---

### Option 2

Declare the child as abstract.

```java
abstract class SavingsAccount
        extends BankAccount{

}
```

Now,

`SavingsAccount` passes the responsibility to its future child classes.

# 🎯 Key Points

✅ An abstract method has only a declaration.

✅ It contains no implementation.

✅ It forces subclasses to implement the required behavior.

✅ If a subclass does not implement it, that subclass must also be declared abstract.

✅ An abstract method defines **WHAT** should happen, while the child class defines **HOW** it happens.

---

# 🎤 Interview Questions

### Q1. What is an abstract method?

**Answer:**

An abstract method is a method declared with the `abstract` keyword that has no implementation. It defines a contract that must be implemented by concrete subclasses.

---

### Q2. Why doesn't an abstract method have a body?

**Answer:**

Because its purpose is to let child classes provide their own implementation. If the method had a body, it would no longer be abstract.

---

### Q3. Can an abstract class contain only abstract methods?

**Answer:**

Yes.

It can also contain concrete methods, constructors, variables, static methods, and final methods.

---

### Q4. What happens if a child class doesn't implement an abstract method?

**Answer:**

If the child class is concrete, the compiler reports an error. If it is declared abstract, the responsibility is passed to the next subclass.
